# Aivory v2.5.2-beta.5

Test release covering all changes since **v2.5.2-beta.4**. Adds reply-completion notifications, model access controls by user group, Tencent Cloud Yuanbao and DeepSeek search, independently configurable web reading, and clearer channel model discovery errors.

## Search and Web Reading

- Add **Yuanbao** to **Admin > Tools**. Use Tencent Cloud SecretId/SecretKey credentials, with optional result mode, industry, publication window, and site filters. Retain returned page bodies, excerpts, dates, and available image metadata. Keep requests compatible with the lite plan by omitting the result-count parameter and applying the requested limit locally.
- Add **DeepSeek** search through its official Search API. Support 1–50 results per query, original-question context, optional IP localization, and query operators such as `site:`, `lang:`, `after:`, and `before:`. Request available page bodies by default and use the long summary when a body is unavailable.
- Add an independent **Web reading (Fetch)** section in **Admin > Tools**, using the existing custom selectors and form styling. Choose **Built-in**, **DeepSeek**, or **AnySearch** separately from the search provider.
- Keep **Built-in** as the default: read the target page directly, then use the optional Jina-compatible Reader fallback when needed. Administrators can override the Reader address and choose escaped or raw target URLs; leaving those settings empty inherits the deployment environment.
- Add DeepSeek Fetch and AnySearch Extract with separate reader credentials. DeepSeek requires an API key; AnySearch supports optional credentials and anonymous extraction. Preserve readable text and available page-image metadata through the existing `web_fetch` tool, including Deep Research.
- Resolve the reader configuration once per invocation so batch requests use one consistent provider. Apply administrator changes on the next invocation. Validate public target URLs and bound response sizes; omit AnySearch quota response bodies that may contain generated credentials.
- Keep returned page text as untrusted external reference material. Improve handling of unconfigured search in ordinary answers and Deep Research without creating placeholder citations.

## Reply Notifications

- Add an opt-in **Notifications** page in user settings. Store the preference for each account on the current device.
- Notify users when a reply finishes while the browser tab is hidden; use native system notifications in the updated desktop app when its window is not focused.
- Open the originating conversation from a notification, including its workspace, while checking the active account. Scope browser service-worker notifications to their originating tab and close delivered notifications when disabled or signed out.
- Bundle the desktop notification runtime with official installers. Older desktop shells indicate that an app update is required before enabling native notifications.

## Model Access and Administrator Diagnostics

- Let administrators allow or deny each user group's access from the model editing page. Hide denied models from that group's catalogs and reject attempts to invoke them directly.
- Enforce group access during chat admission, existing-turn operations, private chat, task execution, and model-backed tools. Preserve workspace restrictions and the existing system-administrator exemption for user-group policy.
- Include access settings in administrator backup and restore, preserve existing access by default, and refresh connected model catalogs after policy changes.
- Improve failed channel model discovery messages with the requested endpoint and a bounded upstream response excerpt. Trim surrounding whitespace from channel API keys when creating or updating credentials.

## Upgrade Notes

- Deploy the updated API and frontend together. Startup migrations add model user-group access storage automatically; existing models remain available to all groups until restricted.
- Configure search and reading independently in **Admin > Tools**. Environment fallbacks include `FETCH_PROVIDER=builtin`, `FETCH_API_KEY`, and the existing `AIVORY_TOOLS_WEB_FETCH_JINA_*` variables. Deployment examples and both configuration references document the precedence.
- Desktop installers bundle the new frontend and notification runtime and retain the saved server address on upgrade.
- After installers finish publishing, deployment administrators must select this version and its matching installers in **Admin > System > Desktop Client**, enable publication, and save. Publishing this GitHub prerelease does not automatically change a deployment's desktop publication settings.
- This is a prerelease. The latest stable release remains **v2.5.1**.

Assets and image tags become available as their workflows finish. The sandbox source is unchanged from beta.4, so source-aware updaters can retain an already-current sandbox.

## Validation

The search and reader changes passed the complete tools test suite with race detection, targeted administrator settings/search/onboarding tests, search and Deep Research regression tests, Go build and vet, TypeScript checking, scoped ESLint, and the production frontend build. Real-browser checks covered independent search and reader settings, custom selectors, credential masking, save/reload behavior, and desktop/mobile layouts across five languages. Provider integrations were verified with simulated responses rather than live paid API credentials.

Release preparation verifies package and lockfile version consistency, unchanged dependency definitions, focused notification and administrator frontend tests, desktop tests, and the production build. CI builds the tagged source, verifies desktop bundles and macOS signatures, and publishes release artifacts.
