# Aivory v2.5.2-beta.7

Test release covering all changes since **v2.5.2-beta.6**. Protects stored files against uncertain database commits and concurrent cleanup, repairs missing-file references before full exports, hardens interrupted backup restores, and fixes HTTP-origin UUID generation and mobile navigation menus.

## Stored Files and Backup Exports

- Reconcile failed database commit acknowledgements when saving uploads, documents, PPT mirrors, and tool artifacts. Treat a verified commit as successful and retain file bytes when the outcome remains uncertain.
- Coordinate file writes and physical cleanup across API processes sharing the same storage. Cleanup rechecks database references while holding the storage lock, and new files use exclusive creation to prevent accidental overwrites.
- Before exports that include files, remove records for confirmed missing local artifacts, uploads, and documents, and clean their references in messages, shared transcripts, compaction media, PPT decks, and skill assets. Document removal also queues vector cleanup through the normal lifecycle.
- Preserve message text, tool-call pairs, conversation branches, and healthy files in mixed artifact groups. Missing uploaded attachments keep a filename and deleted marker; artifact-only messages retain a readable unavailable-file notice.
- Abort repair on unavailable storage roots, access errors, or unsafe paths. Database-only exports do not perform missing-file repair.
- Pin a filesystem snapshot before archive compression so normal deletion cannot invalidate exported database references. Release the storage lock after pinning, allowing writes to resume during compression and Qdrant export.
- Recheck structured file references when an assistant reply finishes so an older generation cannot reintroduce references removed by repair. Validate skill asset source files before saving skill configuration.

## Backup Restore Recovery

- Coordinate full restores with file writers before replacing live directories. Reconcile database commit errors using a witness written in the restore transaction.
- Write persistent recovery journals before publishing restored directories. If a restore crashes, rollback fails, or its commit outcome cannot be verified, retain recovery state and block subsequent storage changes until an operator reconciles it.
- Preserve previous file trees and required Qdrant compensation archives. Store Qdrant recovery ZIPs beside the persisted upload root rather than in temporary process storage.
- Mark archived assistant replies in `streaming` or `stopping` state as interrupted, preserve their partial content, and clear old generation and compaction leases. Prevent old workers from finalizing those restored replies.

## HTTP Compatibility and Interface

- Generate UUIDs on HTTP origins where `crypto.randomUUID()` is unavailable, using cryptographically secure random bytes. Apply the helper to requests, chat layout, email configuration, and reply notifications.
- Keep mobile account menus, language and workspace submenus, and conversation move menus inside the visible viewport. Support submenu back navigation, long scrollable lists, and sidebar safe-area spacing.
- Align administrator audit and tool log empty states with usage logs.

## Upgrade Notes

- Deploy the updated API and frontend together. These changes require no database schema migration.
- Exports that include files now repair confirmed missing-file metadata in the live database before creating the archive. This removes broken references; it cannot recover bytes that are already missing. Conversation text and branches remain available.
- An interrupted restore may leave `.aivory-storage-*.lock.recovery` journals beside the storage roots. Follow the recovery procedure in [`deploy/README.md`](https://github.com/hjxwz123/Aivory/blob/v2.5.2-beta.7/deploy/README.md) or [`deploy/README.zh-CN.md`](https://github.com/hjxwz123/Aivory/blob/v2.5.2-beta.7/deploy/README.zh-CN.md) before removing them or resuming storage writes.
- Desktop installers retain the saved server address on upgrade. After installers finish publishing, deployment administrators must select **v2.5.2-beta.7** and its matching installers in **Admin > System > Desktop Client**, enable publication, and save for their users to receive the update.
- This is a GitHub prerelease. The latest stable release remains **v2.5.1**.

Release workflows publish these tags for **linux/amd64** and **linux/arm64**:

Assets and image tags become available as their workflows finish. The sandbox source is unchanged from beta.6, so source-aware updaters can retain an already-current sandbox.

## Validation

Storage validation covers lost commit acknowledgements, concurrent writers and cleanup, missing-file repair, stable file snapshots, late reply finalization, interrupted generations, failed rollback, and process termination during restore. New fault and concurrency tests also passed with Go's race detector, and `go vet` passed for the affected storage, store, tools, and API packages.

Release preparation verifies version consistency, the production frontend build, HTTP UUID and reply notification regressions, administrator audit logs, desktop tests, and mobile navigation in a real browser. CI builds the tagged source, verifies desktop bundles and macOS signatures, and publishes the release artifacts.
