# Aivory v2.5.1

Stable release collecting all changes since **v2.5.0**, including the final behavior of all sixteen 2.5.1 beta releases and the fixes published after beta.16.

Aivory now has a locally bundled desktop client, interactive visual answers, richer search and research, model-owned request protocols, priority-based channel failover, and a redesigned administrator console. This release also strengthens account isolation, access revocation, resource deletion, voice billing, and usage accounting.

## Desktop App for Windows, macOS, and Linux

- Add an Electron desktop application with the same conversations, streaming, files, settings, and administrator interface as the web application.
- Bundle the frontend, scripts, styles, fonts, and UI assets inside the application. The frontend runs at a local virtual HTTPS origin; API requests go to the configured Aivory server. The app does not load the remote website as its main interface or start a local HTTP server.
- Let official installers start without a hard-coded deployment address. Ask for the server's root URL on first launch, save it locally, and retain it when updating the app. Deployment-specific builds can provide `AIVORY_DESKTOP_BASE_URL`; saved settings support later launches without re-entry.
- Keep credentials in persistent partitions scoped to the configured server. Preserve streaming, cancellation, file transfers, voice WebSockets, payment windows, and public links when using the local frontend.
- Support account/password login and **Sign in with browser**. Build browser authorization URLs from the configured server, use S256 proof with short-lived single-use credentials, and protect cancellation, expiry, and competing login attempts.
- Keep third-party sign-in in the system browser, followed by desktop authorization. Use the real server origin for browser-bound features such as passkey registration.
- Record the initiating desktop device in login history, sessions, feedback, and audit information, instead of reporting the authorization browser as the app's device.
- Show a local offline state without exposing the server URL. Preserve the current page and composer drafts, and recover authentication when connectivity returns.
- Minimize the main window when its close control is clicked. Retain the Dock/taskbar icon and provide an explicit **Quit** action through the application or tray menu. Add the Aivory icon to the macOS menu bar and Windows/Linux system tray.
- Integrate macOS window controls with the active theme, sidebar, and content. Correct drawer positioning, overlay coverage, fullscreen titlebar spacing, and the black screen caused by minimizing before fullscreen exit completed.
- Remove the desktop login welcome heading and subtitle, and use the shared UI typography on the authorization page.
- Add **Admin > System > Desktop client** at `/admin/settings/desktop`. Administrators can publish official packages or a custom version with platform-specific installer URLs. Users receive a simple update prompt when a newer package exists for their platform; accepting opens its download URL.
- Configure the web **Download App** link and visibility separately from update publication. Show it on the new-conversation screen and avatar menu, and hide it inside the desktop app.
- Build Windows x64, Linux x64, macOS arm64, and macOS x64 installers on native GitHub Actions runners. Check package names, versions, bundled frontend/runtime files, and macOS signatures before attaching installers and SHA-256 checksums.

## Interactive Visual Answers

- Add **Generative UI** directly inside assistant replies using versioned `aivory-ui` JSON or self-contained `aivory-html`. Ordinary Markdown tables and ordinary HTML previews retain their existing behavior.
- Provide metrics, steps, tabs, accordions, responsive cards, rich tables, line/area/bar/stacked-bar/horizontal-bar/pie/donut/scatter charts, heatmaps, and gauges. Chart users can inspect values, toggle series, and view the underlying data.
- Support rich table cells containing text, descriptions, links, lists, and external HTTP(S) images. Include filtering, column alignment/widths, captions, sticky headers, and contained scrolling. Images fit their cells without stretching or cropping; loading and error states keep stable dimensions.
- Add editable function graphs. Users can add, edit, hide, or remove functions, change parameters and ranges, zoom, and inspect coordinates.
- Add configurable calculators with live formula results, checklists, and quizzes. Formula evaluation uses a bounded expression parser instead of arbitrary JavaScript execution.
- Render question selectors and common HTML-style form controls in the reply itself. Submitting a completed selection or form sends a normal follow-up to the conversation; no separate form popup is required.
- Support regular, inline-child, private, and shared conversations, with read-only interactive controls for shared content where appropriate.
- Encourage the enabled `generative-ui` skill to choose useful, concise visual presentations when they improve reading or understanding, including requests that do not explicitly ask for a visualization. The skill remains subject to model bindings, administrator enablement, and permission controls.
- Keep generated HTML isolated in opaque sandboxed frames. Block network access, navigation, remote assets, cookies/storage, parent access, and the desktop native bridge; accept only bounded height updates.
- Improve live HTML streaming by updating only at complete script/style/tag boundaries and retaining the last working preview while the next fragment is incomplete. Add loading, error, and retry states instead of leaving a blank frame indefinitely.
- Repair recoverable JSON mistakes, including unescaped quotes inside text, before applying component, nesting, numeric, URL, and resource validation. Accept a standalone supported component inside an explicit `aivory-ui` fence and normalize it into the document format.
- Clarify that UI is assistant answer content, not an `aivory_ui` or `aivory_html` tool call. Apply the output contract to model-bound and manually selected presentation skills, including customized instructions. Raw JSON paragraphs, user-message fences, reasoning, and tool results do not execute the UI protocol.
- Remove the inline **View source** action. Retain the rendering and isolation limits in code, while keeping the skill instructions concise.
- Upgrade untouched shipped skill instructions by fingerprint and preserve administrator-customized prompts and existing bindings. Remove retired embedded prompt documents.

## Skills, Composer, and Conversation Sharing

- Include permitted, enabled administrator skills in `/` selection without requiring users to copy them into their personal library. Preserve compatibility with older servers through the personal-library fallback.
- Add a **Skills** submenu to the composer plus menu to inspect, add, disable, or restore model-bound defaults and manually selected skills. Synchronize it with `/`; show skill names in the plus menu and descriptions in slash selection.
- Preserve the instruction authority of each path: model-bound skills use their system-level loading path, while explicitly selected skills use user-level context for the current turn.
- Let users disable or restore model defaults for the current conversation. Scope saved exclusions by account and conversation, and filter disabled skills from previous tool-loading exchanges before building the next request.
- Deduplicate model-bound, explicitly selected, and tool-loaded skills. Explicit selection takes precedence for the current turn, including an edited personal copy; selecting a disabled default with `/` does not silently restore its saved default for later turns.
- Preserve selections and exclusions through queued turns, withdrawal, regeneration, fallback models, and conversation forks. Recheck permissions and availability server-side.
- Move folder upload and knowledge-base selection into the shared plus menu. Remove redundant Research and Verification descriptions and soften selected-control styling.
- Animate composer height changes when text, skills, or resources change, respecting reduced-motion preferences and the visible mobile viewport.
- Add **Share as link** and **Share as image** in the conversation share submenu on desktop and mobile. Select messages using checkboxes in the chat area, preview the result, and save branded PNG images.
- Generate share images locally in the browser or desktop app; do not upload the generated image to the server. Split long selections into multiple images and preserve selections after capture errors.
- Add independent wrapping controls to every code block and an account-level default in **Settings > Appearance**. Synchronize the default across devices, preserve block overrides through streaming, and keep copying, execution, HTML preview, and sharing based on the original code.

## Search, Images, and Deep Research

### Search Providers and Result Content

- Add **AnySearch** using its fixed official endpoint, `https://api.anysearch.com/v1/search`, with an optional API key and anonymous access. A custom Base URL is not offered.
- Support AnySearch's `max_results`, capability `tag`, `zone`, `language`, extended `params`, and `format`. Default to 10 results per keyword within its 1-10 limit.
- Use bounded concurrent multi-keyword search batches, with up to five keywords. Send a separate documented `query` request for each AnySearch keyword rather than an unsupported upstream `queries` parameter.
- Default DuckDuckGo, Serper, Brave, Tavily, and AnySearch to 10 results per keyword. Remove the old 320-character snippet truncation.
- Preserve provider-supplied page content alongside snippets, citations, dates, and available image metadata, including when merging keyword batches. Request Markdown raw content from Tavily. Snippet-only results still require a separate page fetch when the model needs full text.
- Preserve AnySearch HTTP status and request IDs for diagnosis. Suppress anonymous quota-error bodies that may contain generated passwords or API keys from ordinary tool logs and assistant-visible errors.

### SearXNG and Image Search

- Let the model adapt SearXNG categories, freshness, language, starting page, safe-search settings, and engine selection to the request. Per-call engines remain constrained by the administrator's allowed list.
- Add an administrator-configured SearXNG result count of 1-50 per keyword. Treat the saved count as authoritative even when older tool calls include `top_k`.
- Fetch additional pages only when required, preserve filters, deduplicate results, and return available results if a later page fails or the search deadline is reached. Preserve complete snippets.
- Parse configured SearXNG engines with commas only, preserving names containing spaces such as `google cse`. Keep the saved result-count and pagination behavior through the later search-provider changes.
- Add image-category search and a responsive gallery with source links, full-image previews, thumbnail fallbacks, and unavailable-image states. Preserve ordinary-search thumbnails without forcing a gallery into every reply.
- Retain image metadata from HTML page reads and Jina-compatible Markdown. Let `web_fetch` expose these images when requested, without separate server-side image downloads.
- Preserve image metadata through streaming, saved history, public shares, and administrator conversation inspection.

### Deep Research

- Replace the single search-and-verify pass with iterative search, full-page reading, and reflection. Read sources against their sub-questions, extract dated facts and relevance, follow useful leads, and record research progress.
- Cross-validate reading notes into confirmed, disputed, and unverified findings before writing the report. Expose the live phase and research log in the research panel, and record source-reading model calls separately in usage logs.
- Give research rounds a time budget separate from validation and report writing. Defaults allow up to eight rounds, at least twelve relevant sources read in full, a twenty-minute research budget, and a forty-five-minute overall limit.
- Make research available to eligible models whose custom built-in tool list does not include ordinary web search; global, group, and workspace policies still apply. Administrators can lower the documented `AIVORY_LLM_DR_*` limits to control cost and duration.

## Model Protocols, Channels, and Failover

- Move the request protocol from the channel to the model. Channels provide transport addresses, credentials, request headers, and supported actual model IDs; every scheduled channel for a model uses that model's selected wire format.
- Offer provider/format choices for OpenAI Chat Completions, OpenAI Responses, Anthropic Messages, Gemini GenerateContent, OpenAI Images, OpenAI Embeddings, native DashScope Embeddings, TypeSafe Decisions, and OpenRouter Decisions, with model-kind validation.
- Discover or manually edit each channel's supported request IDs. Put the model's actual request ID before channel selection and restrict bindings to channels that support it.
- Configure all model channels in one priority queue. Smaller priority numbers run first; weights distribute the initial choice within one priority. On failure before visible output, try remaining channels at that priority and then subsequent priorities.
- Fold legacy fallback-channel bindings into later queue priorities. Keep **timeout fallback to another model** as a separate feature; it uses the fallback model's own protocol and bindings.
- Forward a usable channel's first visible text, thinking, or tool event immediately. Once output from the current upstream request has been displayed, do not restart that request on another channel after failure. Preserve the successful channel for subsequent requests in the same turn.
- Apply routing to chat, internal model calls, and image generation. Attribute attempts, usage diagnostics, and health counters to the channel actually serving them.
- Keep one global **First-token timeout (seconds)** at `/admin/settings/model-policy`. Its existing measurement starts immediately before the upstream HTTP request and ends at the first response-body byte, excluding local RAG, context preparation, and billing preflight. It is not a per-model timer.
- When a timeout fallback model is configured, switch only if the original request returns no bytes within the threshold. With only timeout auto-disable enabled, observe late first bytes without cancelling the current response. Zero disables timeout monitoring.
- Add consecutive-error and consecutive-timeout auto-disable rules per model/channel binding and across an entire channel. Temporarily exclude the affected binding or channel for its configured recovery duration, then restore eligibility.
- Show channel-wide and partial-model disable states, affected models, expiry, and manual recovery. Recovering a channel-wide suspension does not clear independent model suspensions; manually disabled channels remain visible and ineligible for scheduling.
- Configure custom channel headers as a JSON object and attach them to upstream requests. Fix PostgreSQL channel-model upserts by specifying the existing case-insensitive unique conflict target.
- Keep model icons and descriptions in basic configuration and organize advanced settings into focused tabs and collapsible sections. Match channel create/edit layouts and place priority, weighting, and upstream cache guidance beside the relevant controls.

## Decisions and Embedding Compatibility

- Add a dedicated **OpenRouter > Decisions** protocol (`openrouter.decisions`) targeting `/api/alpha/decisions`. Accept both `https://openrouter.ai/api/alpha` and the complete endpoint URL.
- Recognize model IDs containing `decision`, as well as supported Jev IDs, during discovery. Preserve explicitly selected discovery protocols and show localized model kinds.
- Accept OpenRouter response IDs, provider names, costs, and alias-resolved served model names. Treat response model names as informational unless an explicit expected release is configured.
- Accept compatible TypeSafe responses with omitted token usage and count missing usage as zero for settlement. Continue rejecting malformed supplied usage rather than silently treating it as free.
- Require the requested decision value and valid confidence or a usable probability distribution for choice/score answers. Derive confidence from a supplied distribution when possible, retain `noul` probability requirements, accept omitted type metadata when the request already identifies it, and reconstruct score legends when needed.
- Support Aliyun's compatible System One schema through the TypeSafe protocol: resolve `/compatible-mode` to `/compatible-mode/v1/systemone` and serialize structured question instructions for that endpoint.
- Preserve status codes and request IDs when an HTTP 200 response fails decision validation. Record sanitized request/response details through administrator call diagnostics instead of exposing upstream bodies to ordinary users.
- Stop interpreting every generic `/api/v1` gateway as native DashScope Embeddings. Preserve saved and explicitly selected protocols.
- Keep Aliyun OpenAI-compatible embedding URLs unchanged: a channel ending in `/compatible-mode` with **OpenAI > Embeddings** continues to use `/compatible-mode/v1/embeddings`, including `text-embedding-v4`.
- Split oversized OCR paragraphs, tables, code blocks, and long individual lines before embedding. Preserve UTF-8 text and chunk/vector ordering, account for headings and overlap, and leave headroom below known model input limits.

## Account Isolation, Resource Cleanup, and Billing

- Clear conversation, workspace/project, private-panel, and pending-request state when identity changes. Abort old local stream readers and invalidate reconnects/delayed sends so a previous account's generation cannot appear in the next account.
- Remove persistent private-image caching from the service worker, clear legacy caches, and return private files/artifacts with `Cache-Control: private, no-store`.
- Stop message-following connections when workspace membership is revoked, including followers of another member's active reply, without cancelling that member's generation.
- Apply regular-chat user concurrency and daily-message limits to private chat.
- Protect RAG ingestion against deletion races using write leases and deletion tombstones. Remove vectors written after a document disappears, retain failed vector deletion for retry, and reject zero-row terminal status updates.
- Delete conversation sandbox sessions and archives through a durable cleanup path. Retry physical cleanup failures and retain stored bytes referenced by other conversations or knowledge bases.
- Include sandbox sessions, workspace archives, documents, files, and generated artifacts in account deletion. Prevent idle sandbox recycling from creating fresh archives for deleted accounts.
- Track avatar ownership and cleanup state. Queue replaced, removed, failed, and deleted-account avatar objects for deletion; require a live ownership reference when serving an avatar and disable caching.
- Browse a bounded saved workspace archive when a sandbox session has expired, without creating a replacement container merely to inspect files. Provide explicit unavailable reasons when an archive or compatible sidecar is missing.
- Include Gemini thinking tokens in output billing and daily token accounting across streaming and non-streaming responses.
- Calculate workspace monthly usage from durable statistics rather than removable diagnostic logs, so deleting logs does not reset members' consumed allowance.
- Treat upstream errors containing `inappropriate` as moderation blocks alongside existing sensitive-word errors.

## Voice Recognition and AI PPT Pricing

- Add browser speech recognition as an alternative to server-side transcription. Let users select their default engine, see availability/cost, and receive clear fallback, microphone, permission, network, and balance messages.
- Price server transcription per second in USD converted through `credits_per_usd`; partial seconds round up. Keep browser recognition free, zero-price services free, and administrator exemption behavior.
- Support continuous Volcano recognition with renewed upstream segments, bounded audio queues, and preservation of all recognized text. Default to no total recording deadline, five-minute segments, a 64 MiB segment byte threshold, and a thirty-second audio buffer.
- Discard the oldest unsent audio when the queue is full instead of allowing recording memory to grow indefinitely. Network failures, provider errors, permission revocation, or insufficient balance can still stop recognition.
- Reserve and settle live-transcription credits per segment using the PCM actually forwarded. Bound WebSocket message size, upstream responses, decompression, and network waits; retain the older single-connection contract for older clients.
- Verify uploaded audio duration from WAV samples or decoded compressed audio instead of trusting client duration. Withhold uploaded transcription results when settlement fails. Include `ffmpeg` in the application image; native server installations need it in `PATH` for compressed formats.
- Price AI PPT generation and edits in USD while preserving older credit-denominated settings until a USD value is explicitly saved.

## Upgrade from v2.5.0 or a 2.5.1 Beta

Back up the database, uploaded/generated files, and workspace archives. Keep the deployment's existing `.env`, secrets, Compose project, ports, and data paths. Upgrade the API and web frontend together; the application image contains both.

SQLite and PostgreSQL migrations run automatically. They add model protocol/binding/health fields, audit/tool diagnostics, usage timing, draft bookkeeping, resource cleanup state, avatar ownership, and skill exclusions. Legacy configuration fields remain readable, but older executables do not implement all new routing or cleanup behavior; use a backup for a coordinated rollback.

- Existing explicit model protocols are preserved. Missing protocols migrate from the previous primary channel's format. A model already saved with an incorrect native DashScope protocol on a generic OpenAI gateway needs manual correction to **OpenAI > Embeddings**.
- Existing fallback-channel bindings migrate to later regular queue priorities. Existing positive global timeouts are preserved; on the first migration, the largest positive legacy model timeout may seed a missing/zero global value. Review **Model policy** after upgrading if older models had individual timeouts.
- Untouched built-in Generative UI instructions update automatically; administrator-customized instructions remain. Custom prompts can adopt the new component examples and output/quote guidance manually.
- Existing MCP tools start enabled unless explicitly excluded. Tool diagnostics default to recording failures only.
- Existing SearXNG result-count settings remain authoritative. Separate allowed engines with commas. The ten-result defaults and retained page content of other services can increase search charges and model context usage.
- Install the new desktop client to receive the local frontend, updated window behavior, and segmented voice transport. Server URL/settings persist through app updates. Administrators must enable/publish a platform package for client update prompts.
- Refresh an older updater container once to enable source-aware sandbox updates. Use the current deployment file while preserving local deployment customizations.

For the full production stack, set these values in the active `deploy/.env`:

```dotenv
IMAGE_TAG=2.5.1
UPDATER_IMAGE_TAG=2.5.1
```

Remove or align explicit `APP_IMAGE_TAG` and `SANDBOX_IMAGE_TAG` overrides, then deploy after all release images are available:

```bash
cd deploy
docker compose --env-file .env -f docker-compose.prod.yml config --images
docker compose --env-file .env -f docker-compose.prod.yml pull
docker compose --env-file .env -f docker-compose.prod.yml up -d --no-build
```

To refresh only the updater before using the website's update action, first set `UPDATER_IMAGE_TAG=2.5.1`, then run in the active deployment directory:

```bash
docker compose --env-file .env -f docker-compose.prod.yml pull updater
docker compose --env-file .env -f docker-compose.prod.yml up -d --no-deps updater
```

Personal deployments should retain their existing profile and substitute `.env.personal` and `docker-compose.personal.yml`. See the [deployment guide](https://github.com/hjxwz123/Aivory/blob/v2.5.1/deploy/README.md) for source-aware updates and deployment options.

Continuous Volcano defaults can be overridden explicitly:

```dotenv
AIVORY_API_AUDIO_STREAM_MAX_SESSION=0
AIVORY_API_AUDIO_STREAM_MAX_BYTES=67108864
AIVORY_API_AUDIO_STREAM_SEGMENT_SESSION=5m
AIVORY_API_AUDIO_STREAM_BUFFER_SECONDS=30
```

## Known Limitations and Validation

- macOS packages are ad-hoc signed and signature-checked when Developer ID credentials are absent. They are not Apple-notarized; the stable version label does not remove macOS trust prompts.
- Administrator deletion of an uploaded file can still delete document indexes in other conversations or knowledge bases sharing its storage path. User-facing deletion is scoped; this remaining administrator-path limitation is not presented as fixed by the resource cleanup changes.
- The UI output contract discourages hallucinated `aivory_ui`/`aivory_html` tool calls, but does not automatically convert arbitrary invalid calls into a visualization. Nonexistent tools remain rejected.
- Search content depends on the provider and the available results. Retaining supplied full text does not imply that every provider returns full text for every result.

The beta series included frontend, Go, sandbox, Electron, and real-browser regression checks appropriate to the individual changes. The post-beta.16 UI fixes passed their targeted checks before publication. This stable release preparation verifies version/lockfile consistency, release scope, and packaged artifact publication without rerunning a full application test suite or live paid-provider requests. Release CI builds the tagged web/API source, checks desktop bundles/signatures, and publishes multi-architecture images.
