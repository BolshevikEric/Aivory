# Aivory v2.5.2-beta.10

Test release covering changes since **v2.5.2-beta.8**. Makes workspaces optional for registration domain rules, fixes missing cache token counts in usage logs, unifies empty and error states, and adds optional You.com search. This release includes the changes prepared for the unpublished beta.9 draft.

## Registration Domain Rules

- Create a domain rule without selecting a workspace, including when no workspaces exist. Matching new accounts retain personal space and do not receive workspace membership. Email verification, initial user group and subscription purchase policies still apply.
- Remove workspace icon and description editing from the domain rule form and workspace icons from the rule list.
- Disable personal-space locking when no workspace is selected. Clearing the workspace selection also clears the lock; API validation prevents rules and individual member overrides from locking personal space without a workspace.
- Preserve existing member bindings, initial-group behavior and individual lock overrides when editing rules. Changing matched domains or stopping automatic enrollment does not remove existing members. A rule's target workspace remains immutable after creation.
- Automatically migrate existing databases to support rules without a workspace while preserving rule keys, matched domains and member bindings.

## Cache Usage and Pricing

- Preserve cache read and write token counts from OpenAI Chat Completions and Responses, including common compatible gateway counters. Read Gemini's cached prompt token count in streaming and prompt-tool responses.
- Accumulate cache usage across tool rounds and preserve reported usage when a later request is interrupted. Repeated cumulative usage frames do not multiply the counters, and a later frame that omits cache details does not erase an earlier count.
- Request streaming usage in OpenAI's prompt-tool mode, so those calls can also populate the usage log.
- Price cached input separately for protocols whose input total already includes cached tokens, avoiding duplicate input charges. Anthropic's separate input and cache accounting remains supported.
- Verify the provider-to-log path for all four protocols, the admin API's JSON fields, and cache values in both the usage table and call details.

## UI Consistency

- Use shared empty-state components across administration tables, file lists, knowledge bases, projects, prompts, skills and presentation pages.
- Align empty-state spacing, icons and text hierarchy, and preserve the surrounding table structure where appropriate.
- Show explicit load failures with retry actions and keep existing records visible during refreshes.
- Make table loading and error feedback consistent across the administration pages.

## Search and Administration

- Add optional You.com web search, with keyed and keyless request modes, citation parsing and bounded rate-limit retries. Administrators can select it in search settings.
- Apply saved You.com credentials immediately and honor an explicitly cleared key over environment defaults.
- Remove deleted channel model capabilities across subsequent saves.
- Fail model association reads explicitly so a failed configuration load cannot silently clear existing model bindings.
- Update the bilingual project documentation and the built-in generative UI guidance.

## Upgrade Notes

- Deploy the API and frontend together. Startup automatically makes the domain-rule workspace column nullable. SQLite rebuilds the table while preserving dependent rows; PostgreSQL drops the column's NOT NULL constraint.
- Cache counters apply to new requests after deployment. Historical rows already stored as zero cannot be reconstructed from those rows alone.
- A cache count can legitimately be zero when no cache was used or the upstream omitted that metric. Gemini's generation usage does not report cache writes; a DeepSeek cache miss is ordinary input, not proof of a cache write.
- After the desktop installers finish publishing, administrators can select **v2.5.2-beta.10** and its matching installers in **Admin > System > Desktop Client** to publish the update to their users.
- This release is marked as a GitHub prerelease.

- Targeted search, model binding and channel capability regressions.
- UI state browser checks, frontend tests, TypeScript checking and the production frontend build.
