# Aivory v2.5.2-beta.6

Test release covering all changes since **v2.5.2-beta.5**. Adds administrator-controlled site closure, combines website availability and messages on one page, introduces localized account emails and password-reset links, supports multiple sending accounts, and shows cache reads and writes in call logs.

## Website Access and Notifications

- Combine **Website access**, **Popup messages**, and **Notifications** into one continuous **Admin > System > Website & notifications** page. Keep each section's save and management controls together, with no tabs between these three sections. Existing administrator URLs continue to reach the combined page.
- Add a **Close website** switch with an optional plain-text message of up to 2,000 characters. Preserve line breaks; an empty message uses the current website language's default maintenance text.
- Enforce closure at both the frontend and API. Pause ordinary users' business requests, including conversations, uploads, files, maps, and public shared content. Keep authentication, password recovery, health checks, and payment settlement callbacks reachable.
- Let active system administrators continue using the console and reopen the site. Validate their current database role and session so demoted, suspended, or revoked accounts cannot retain the exemption.
- Update already-open pages through status polling, focus checks, and structured API closure responses. Restore access when the site reopens. The maintenance page follows the website theme and language and displays no administrator login entry; administrators can navigate directly to `/login`.

## Account Emails and Password Recovery

- Send redesigned registration and recovery emails in the selected website language, supporting Simplified Chinese, Traditional Chinese, English, Japanese, and French.
- Replace recovery codes with expiring password-reset links. Carry the selected language into the reset page and reject expired, reused, or invalidated links.
- Send a welcome email after registration completes, introducing chat, image generation, and other available features. Send membership activation and renewal messages with the assigned user group and validity period.
- Provide a dedicated suspended-account page with contact information and account-switching controls.
- Support multiple SMTP sending accounts in **Admin > System > Email service**. Preview each email type and choose its sending account separately. Welcome and membership emails can be disabled; registration verification and password recovery remain mandatory and allow sender configuration.

## Call Logs and Interface

- Show cache-read and cache-write token counts in administrator call logs, using the usage fields normalized from the supported provider protocols.
- Move the two home-page corner controls upward to improve their placement.

## Upgrade Notes

- Deploy the updated API and frontend together. Website closure defaults to off on deployments without a saved setting.
- The closure setting is stored with administrator settings and travels with exported backups. A restored site can remain closed until an administrator reopens it from the combined page.
- Desktop installers bundle the updated frontend and retain the saved server address on upgrade.
- After installers finish publishing, deployment administrators must select **v2.5.2-beta.6** and its matching installers in **Admin > System > Desktop Client**, enable publication, and save for their desktop users to receive the update.
- This is a GitHub prerelease. The latest stable release remains **v2.5.1**.

## Validation

The website-access change passed focused Go access-control and administrator-login tests, frontend status and navigation tests, TypeScript checking, scoped ESLint, and a production frontend build. Real-browser checks cover the combined administration page, administrator access during closure, ordinary-user and shared-page blocking, automatic closure and reopening, safe custom text, mobile layout, and direct login without a visible administrator entry.

Release preparation also checks localized email delivery and password recovery, cache usage, desktop tests, and version consistency. CI builds the tagged source, verifies desktop bundles and macOS signatures, and publishes the release artifacts.
