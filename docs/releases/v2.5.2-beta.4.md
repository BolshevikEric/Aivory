# Aivory v2.5.2-beta.4

Test release covering all four application commits since **v2.5.2-beta.3**. Adds administrator views for shared conversations and user-group filtering, message-editing permissions at the user-group and workspace levels, clearer preset-component instructions, and neutral colors for workspace switching and source citations.

## Administrator Views

- Add a shared-conversation inventory under **Data and Operations**. Administrators can view shared conversations and links, open or copy a share link, inspect its owner, and navigate paginated results.
- Filter shared conversations by title and user. Keep filters and pagination consistent while requests are loading or returning out of order.
- Filter **Admin > Users** by user group alongside the existing user search, with pagination reset when filters change.

## Message-Editing Permissions

- Add **Message editing** to system administrator user-group permissions. When disabled, hide direct saving of the user's own messages and editing of AI replies. Users can still modify their own messages and resend them as a new branch.
- Add a workspace-wide **Message editing** switch under workspace capabilities and a separate per-member switch under member permissions.
- Require ordinary members to satisfy all three permissions: user group, workspace policy, and member permission. Workspace owners and administrators bypass only the member-level switch; they still obey the workspace policy and applicable user-group restrictions. Site administrators retain their existing user-group exemption without gaining an exemption from workspace access or workspace restrictions.
- Preserve existing conversation access, authorship, guest, archived-conversation, and read-only restrictions. Permission to edit does not grant access to another user's private conversation or allow editing another user's prompt.
- Remove unavailable editing controls immediately when permission changes, including closing an open AI reply editor. Recheck workspace policy and member permission inside the message-save transaction to enforce restrictions on direct API calls and concurrent saves.
- Default existing groups, workspaces, and members to allowed. Preserve explicit denials and omitted fields in partial permission updates.

## Generative UI Instructions and Appearance

- Clarify complete quotes, opening tags, closing tags, and attribute values in the built-in preset-component skill. Put detailed step explanations, Markdown, citations, and nested components in component bodies rather than long text attributes.
- Keep both complete component layouts and components interleaved with Markdown available. Teach documented preset tags and inline SVG, with readable Markdown as the fallback when a valid component cannot be produced.
- Keep legacy structured UI as a parsing compatibility path. Do not teach it in the skill, and remove the custom HTML-page fallback from the built-in instructions.
- Replace the fixed green workspace-switch button and source-number badges with the current theme's neutral colors. Apply the citation styling to both inline references and expanded source lists, including hover states.

## Upgrade Notes

- Deploy the updated API and frontend together. Startup migrations add the workspace policy and member message-editing fields automatically on SQLite and PostgreSQL; no manual SQL is required.
- Existing permission settings remain intact. The new message-editing controls default to allowed until an administrator disables them.
- Administrator-edited built-in skills retain their customization. Review the preset-component skill in the administrator tools if a deployment uses an edited prompt and needs the new syntax guidance.
- Desktop installers bundle the updated frontend and retain the saved server address on upgrade.
- After desktop installers finish publishing, deployment administrators must select this version and its matching installers in **Admin > System > Desktop Client**, enable publication, and save. A GitHub prerelease does not automatically change a deployment's desktop publication settings.
- Clients older than **2.5.2-beta.3** may still contain the previous beta-update filter. If such a client cannot detect an administrator-published beta, install a package from this release manually once.
- This is a prerelease. The latest stable release remains **v2.5.1**.

## Validation

The message-editing changes passed 64 focused frontend tests, targeted API permission and resend tests, the complete store test suite, TypeScript checking, scoped ESLint, and the production frontend build. Real-browser checks covered user-group and workspace controls, permission intersections, live revocation, preserved resending, and desktop/mobile layouts. The neutral-color changes passed scoped ESLint and browser checks in light and dark themes at desktop and mobile widths, including citation popovers and desktop hover colors.

Release preparation checks version and lockfile consistency, unchanged dependency definitions, and the complete commit range. It does not repeat the full application test suite or claim native installer execution on every operating system. CI builds the tagged source, verifies desktop bundles and macOS signatures, and publishes release artifacts.
