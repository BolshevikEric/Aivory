# Aivory v2.5.2-beta.8

Test release covering changes since **v2.5.2-beta.7**. Makes large backup restores resilient to proxy limits and long-running network requests, and adds direct restore from a ZIP already copied to the server.

## Backup Upload and Restore

- Upload full backups in acknowledged chunks and restore them as a background job. The page shows actual upload progress and separately reports validation and restore status.
- Reduce chunk size automatically after a proxy responds with `413 Content Too Large`, down to 256 KiB. This works around smaller per-request proxy limits; `MAX_BACKUP_BYTES` remains the overall archive limit.
- Restore a regular `.zip` or `.ZIP` directly from the configured server backup directory. The archive bytes do not pass through the browser, Cloudflare or the reverse proxy, and the source ZIP is retained.
- Keep the existing archive validation, transactional restore, recovery journals and rollback behavior for both restore sources.
- Update backup status polling and bypass Service Worker interception for long requests, avoiding browser-enforced Service Worker fetch deadlines during uploads and restores.

## Reliability

- Stop background polling requests when their owning page or session no longer needs them.
- End follower event streams promptly when access is revoked.
- Keep restore status checks available through the scoped job capability if the user's login session expires during restoration.

## Upgrade Notes

- Deploy the updated API and frontend together. No database schema migration is required.
- Full backups exported by **v2.5.2-beta.7** use archive format v3, which this release still supports. A complete, valid beta.7 ZIP can be restored directly after upgrading. The archive must contain every file referenced by its database records; an older incomplete archive cannot restore missing file bytes.
- For large archives or proxy `413` errors, copy the ZIP into the displayed `BACKUP_DIR` on the server, refresh **Admin > Backup & Migration**, select it under **Restore from server directory**, and type `REPLACE`. Keep the original ZIP until the restore is confirmed successful.
- For browser uploads, Nginx must allow each chunk request plus multipart overhead. For example, `client_max_body_size 8m;` allows the current 4 MiB maximum chunk. Timeout settings control inactivity between upstream I/O and do not change body-size limits.
- This is a GitHub prerelease. The latest stable release remains **v2.5.1**.
