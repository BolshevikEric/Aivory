# Aivory v2.5.1-beta.16

Test release covering all changes since `v2.5.1-beta.15`: official AnySearch integration, more complete search results, per-tool MCP controls, compatible Decision response handling, resilient Generative UI parsing, quieter administration forms, and a consistent startup experience across web and desktop.

## Search Services and Result Content

- Add **AnySearch** through its fixed official endpoint, `https://api.anysearch.com/v1/search`. Support an optional API key and anonymous requests; do not expose a custom Base URL setting.
- Support AnySearch's `max_results`, capability `tag`, `zone`, `language`, `params`, and content `format`. Default to 10 results per keyword, within the service's 1–10 range.
- Reuse Aivory's bounded concurrent search batches for up to five keywords. Send one documented `query` request per keyword to AnySearch rather than passing an unsupported `queries` field upstream.
- Default DuckDuckGo, Serper, Brave, Tavily, and AnySearch to 10 results per keyword. Remove the old 320-character excerpt truncation.
- Preserve provider-supplied page content alongside snippets, citations, dates, and available image metadata, including when combining multi-keyword results. Request Markdown raw content from Tavily; providers that return only snippets still require a separate page fetch for full text.
- Keep SearXNG's administrator-configured result count, pagination, and search behavior. Parse configured engines using commas only, preserving engine names containing spaces, such as `google cse`.
- Retain AnySearch HTTP status and request IDs for troubleshooting. Suppress quota-error response bodies that may contain automatically generated passwords or API keys from ordinary tool diagnostics and assistant-visible errors.

## Individual MCP Tool Controls

- Add an administrator drawer to browse a service's discovered tools, search by name or description, and inspect input schemas.
- Enable or disable individual tools while keeping the rest of the MCP service available. Persist exclusions across tool synchronization and server restarts.
- Remove disabled tools from model-visible definitions and check availability again when executing a call, including calls referring to an older tool snapshot.
- Include tool exclusions in runtime cache fingerprints and audit snapshots so configuration changes take effect without retaining stale definitions.

## Decision Protocol Compatibility

- Accept valid TypeSafe-compatible decisions when token usage is omitted. Treat missing token counts as zero for settlement; continue rejecting malformed counts rather than interpreting them as free usage.
- Require the requested decision values and either valid confidence or a usable probability distribution for choice and score answers. Derive confidence when only a distribution is supplied; retain the probability value required by `noul` answers.
- Accept omitted answer-type metadata when the requested question already supplies it. Reconstruct score legends from the request when needed and ignore unrelated extra answers.
- Treat response model names as informational unless an explicit expected release is configured. Recognize request IDs from the response header, `request_id`, or `id`.
- Support Aliyun's existing TypeSafe-compatible System One schema without introducing another protocol: resolve `/compatible-mode` to `/compatible-mode/v1/systemone` and serialize structured question instructions as strings for that endpoint.

## Generative UI and Composer Skills

- Recover supported `aivory-ui` documents containing repairable JSON mistakes, including unescaped double quotes inside text and consecutive quoted phrases, before applying the existing component and size validation.
- Add quote-escaping guidance to the built-in Generative UI skill. Update untouched shipped skill defaults while preserving administrator-customized instructions.
- Simplify the composer Skills submenu to show skill names without description text. Keep descriptions available through `/` selection and preserve the existing default-skill and per-turn selection behavior.

## Administration Interface

- Streamline search and sandbox configuration with clearer spacing, responsive field placement, and compact numeric inputs. Correct input widths at their wrapper so controls fit their intended space.
- Remove redundant implementation explanations and repeated hints from tools, document processing, storage, audio, skills, email, and logging settings. Keep configuration fields and relevant validation available.
- Update related administrator and chat translations in English, Simplified Chinese, Traditional Chinese, Japanese, and French.

## Startup and Loading Experience

- Keep the initial Logo, Aivory wordmark, and three-dot loading state. Show a localized slow-loading message after approximately five seconds without displaying estimated percentage progress.
- Show a clear failure state and a manual **Reload** button when an entry script, stylesheet, lazy module, or application startup fails. Remove the lazy-module automatic reload handler to avoid refresh loops.
- Share layout and theme tokens between the static HTML startup screen and React's full-screen fallback. Reserve status space to keep the brand stationary, including on narrow screens and with longer translations.
- Inline the wordmark and startup resources so the complete brand appears before the application bundle downloads. Read saved or browser language before startup and localize messages in all five supported languages.
- Make browser `theme-color` follow the actual selected theme and accent. Use **Aivory** as the default tab title while retaining conversation titles after navigation.
- Allow mobile pinch zoom and show visible JavaScript-disabled guidance above the loading layer. Respect reduced-motion preferences.
- Apply these frontend changes to both the web application and desktop's locally bundled interface. The About version continues to come from the package version on web and the installed application version on desktop.

## Upgrade Notes

Update the API and frontend together. SQLite and PostgreSQL automatically add the MCP tool-exclusion field; existing services start with all previously available tools enabled.

Existing SearXNG result-count settings remain unchanged. Separate multiple configured engine names with commas. Other search services now default to 10 results per keyword, so paid-provider usage can increase and longer result content can consume more model context.

Administrators who customized the Generative UI skill keep their edits; add quote-escaping guidance manually if desired. The sandbox source is unchanged from `beta.15`, so a source-aware updater can retain an already-current sandbox.

Startup changes passed TypeScript, targeted lint and frontend checks, a production build, and 29 browser checks each in development and production before publication. No full test suite was rerun solely for the version bump. GitHub Actions builds and verifies the tagged installers and container images.
