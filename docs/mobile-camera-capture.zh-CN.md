# 移动端聊天拍照更改说明

聊天输入框新增独立的“拍照”入口。用户可从手机调用系统相机，确认照片后将其附加到当前消息；普通聊天和隐私对话均提供该入口。

## 入口和设备范围

| 场景 | 新增入口 |
| --- | --- |
| 普通聊天，视口宽度不超过 639px | “+”菜单中，在“添加图片”之后显示相机图标和“拍照” |
| 普通聊天，较宽视口且主输入设备为粗指针 | 在横向工具栏中显示带提示文字的相机按钮，覆盖触屏手机横屏和平板布局 |
| 隐私对话，窄视口或粗指针设备 | 在图片选择按钮旁显示带提示文字的相机按钮 |

入口使用独立的文件输入：`type="file"`、`accept="image/*"` 和 `capture="environment"`。不设置 `multiple`，请求一次拍摄一张照片；`environment` 向浏览器提示优先使用后置摄像头。点击动作同步打开文件输入，保留调用系统选择器所需的用户手势。

`capture` 是浏览器支持的拍摄提示，最终系统界面及默认摄像头由浏览器和设备决定。不支持该提示的环境可能回退为图片选择器。相机功能不依赖新增的原生插件或 `getUserMedia` 摄像头流。

## 普通聊天照片处理

- 拍照和相册选择使用独立的输入元素；“添加图片”继续保留多选能力。
- 确认照片后直接调用既有 `handleAttach`，与其他图片共用本地缩略图、上传进度、附件移除和消息提交逻辑。
- 复用已有的图片准备逻辑：符合条件的小图片保持原文件，较大或需要转换的图片在浏览器内压缩或转换；上传仍遵守服务端策略与权限。
- 新聊天继续通过既有的对话创建逻辑确定上传归属；已有聊天继续使用当前对话范围。
- 每次选择后清空文件输入的值，使下一次拍摄可再次触发选择事件；取消拍摄或返回空选择时不新增附件。
- 相机入口遵守 `canUploadFiles`，没有上传权限时不显示。图片与当前模型的兼容性仍由既有流程处理。

## 隐私对话照片处理

- 仅在当前模型支持图片，或允许视觉代读，且用户有上传权限时显示入口。
- 相机返回的照片先调用已有 `prepareImageForUpload`，再通过 `readPrivateImage` 转为内存中的图片数据，减少高分辨率照片直接超过 5 MB 上限的情况。
- 图片准备使用现有的默认预算：兼容图片不超过 3 MiB 时保持原文件，需压缩时以略低于 3 MiB 为目标。浏览器无法完成解码或压缩时，保留原文件并执行原有校验。
- 原有的有效图片类型、单张大小、每段对话最多 16 张及请求大小限制继续生效；错误使用已有的本地化提示。
- 本次新增的照片准备和读取都在浏览器内进行，不调用普通聊天的文件上传接口；发送仍使用隐私对话已有的请求流程。
- 正在读取图片或生成回复时禁用相机按钮，防止重复读取；清空对话时同时重置相机输入。

## 布局和语言

- 使用现有 `lucide-react` 的 `Camera` 图标。
- 普通聊天菜单行和触屏工具栏相机按钮提供至少 44px 的操作尺寸。
- 隐私对话相机按钮使用 44px 尺寸；图片按钮及发送区域禁止收缩，模型选择区允许收缩，长模型名截断，避免新增入口挤压操作按钮。
- 图标按钮提供本地化提示和可访问名称；相机文件输入也提供可访问名称。
- 在简体中文、繁体中文、英语、日语和法语的聊天资源中新增 `composer.takePhoto` 与 `private.takePhoto`。

## 审阅和验证范围

按用户要求，未运行本地测试、构建、类型检查、开发服务器或浏览器验证。交付审阅仅包括源码阅读、差异与空白检查、提交范围核对及合并冲突检查。
