# 移动端组件适配与本地前端验证

本次在已有公式编辑器修复的基础上，处理公共弹窗、侧栏、搜索建议、工作区管理、设置页、图片蒙版和 Office/PPT 预览的同类布局问题。核心目标是：手机竖屏、横屏和软键盘压缩可见区域后，内容仍可滚动到达，确认、关闭和重试操作不会被固定尺寸或错误的坐标计算裁掉。

## 问题与设计

原有组件分别使用 `100dvh`、`vh`、固定最小高度、`visualViewport` 和桌面居中位移。浏览器的布局视口与键盘上方的可见视口并不总是一起缩小；Portal 弹层也不能直接继承聊天区的高度。单独给每个组件添加媒体查询，会重复处理安全区，并遗漏可见视口的顶部偏移。

本次采用公共几何来源与显式滚动归属，并允许复杂组件设置自己的短视口回退：

1. 从 `visualViewport` 获取可见矩形，在普通缩放比例下用于弹层定位；没有该 API 时回退到布局视口。
2. 将可见矩形与设备安全区域求交集。键盘已经截去的底部不再重复扣除手势安全区；视口已偏移到顶部安全区下方时也不重复扣除顶部。
3. 多个组件共享一组窗口和可见视口监听，通过动画帧合并更新，先写 CSS 变量，再通知 React 订阅者。最后一个订阅退出时清理事件、动画帧、探针及变量。
4. 页面缩放时保留弹层布局尺寸，避免放大操作被当成软键盘压缩；输入建议菜单则使用原始可见矩形，定位到用户实际能看见的区域。
5. 常规表单采用固定标题/操作栏、正文内部滚动；可见高度不足 240px 时允许整窗滚动。工作区管理和图片蒙版固定控件较多，在安全可见高度不足 360px 时提前切换为整窗滚动。

## 具体更改

| 组件 | 原有问题 | 修改后的行为 |
| --- | --- | --- |
| 公共 Dialog | 居中点及限高只依赖布局视口；全屏仍可能继承居中位移；键盘变化触发尺寸缩放动画 | 按安全可见矩形居中或贴边；新增 `fullscreen`、`mobileFullscreen` 与 `scrollMode`；可见区域变化取消尺寸缩放动画 |
| 公共 Sheet | Portal 侧栏高度与键盘上方区域不一致，安全区可能重复处理 | 四个方向均按同一安全矩形定位；允许明确正文或整侧栏滚动；保留可配置桌面宽度上限 |
| 首次设置密码 | 标题和输入被挤压、手机自动聚焦立即打开键盘、确认字段或提交不可达 | 标题与字段进入真实正文，提交独立 footer；窄屏/短屏/粗指针初始焦点留在弹窗；窄屏输入字体 16px，提交至少 44px |
| 欢迎向导与完成页 | 高度被说明和插画占满，底部继续按钮可能被压缩 | 显式正文和 footer；完成页的正文可滚动，开始使用按钮保留独立操作区域 |
| 工作区管理 | 仅窄屏类名适配，实际自定义 pane 没有接入极短区域回退 | 手机全屏；常规内部 pane 滚动；短区域整窗滚动、单列和横向导航，并同步 ARIA 与方向键；创建/权限/转移弹窗接入正文滚动 |
| 设置页、会话管理 | 直接 Radix Portal 使用布局高度；固定最小高度可覆盖键盘限高 | 设置页接入安全矩形，极短区域取消 sticky header 并整框滚动；会话管理的 min/max 高度都依据可见区域 |
| 图片蒙版编辑器 | 原有 `vh` 尺寸在键盘上方越界，宽横屏下画布可能被工具栏压到接近零 | 使用安全区域尺寸；短区域整窗滚动和单列；画布宿主至少 10rem，提示词与提交可以滚动到达 |
| 全局搜索 | 输入行与结果列表争抢空间，横屏关闭入口不明显 | 窄屏或短可见区域使用紧凑布局，固定输入行并由列表滚动；粗指针平板不会仅因触摸输入而强制全屏 |
| 文件筛选 | 浮层内容超过 Radix 剩余空间或键盘上方空间 | 同时受 Radix 可用高度和公共安全高度约束，内部纵向滚动，宽度受视口限制 |
| 输入区 `/`、`@` 建议 | 混用布局视口 bottom 与可见视口坐标；手动滚动后可能跳回选中项 | 单一 top 坐标系，按上下空间翻转；向上用独立 `translate`；相同几何复用状态，选中项只滚动菜单自身 |
| DOCX、PPTX、XLSX、长文本 | 20rem/28rem 等固定最小高度超出父容器，内滚动末端仍藏在裁剪区 | 建立 `h-full / flex-1 / min-h-0` 高度约束，内容保持自然尺寸；末行、末页和末列可以滚动到达 |
| 预览加载/错误/过大文件 | 垂直居中可能让长提示的开头和重试按钮越界 | 外层可滚动，内容使用安全居中和不收缩的列布局 |
| AI PPT、Docmee 外层编辑器 | 宿主只有固定最小高度或 `75vh`，独立操作栏被编辑区域挤压 | 明确宿主和 DialogBody 高度；操作栏独立；Docmee 长错误 overlay 可滚动且支持长 URL 换行 |
| PPT 模板选择器 | 多行筛选/上传区域和长错误条把列表压成零 | 测量组件实际剩余空间，低于 96px 时改为整个选择器滚动；正常空间保留工具行与列表内部滚动 |

公共 Dialog 未指定 `scrollMode` 时保留旧调用方的滚动方式。原公式编辑器保留专用几何和 MathLive 键盘处理，通用窄屏宽度规则显式排除它；本次增加公式回归场景，确认公共修改没有覆盖已有适配。管理员用户活动侧栏保留原有较宽的桌面尺寸。

## 本地前端验证

验证仅使用本机 Node.js、Vite、Vitest 和已安装的 Edge。没有启动后端服务，也没有运行 Python、Go、桌面应用测试或手动触发远端测试/部署。

### 新增单元测试

新增 18 项全部通过：安全区与可见矩形求交集、缩放回退、先写变量再通知、共享订阅及待执行帧清理，以及建议菜单方向、偏移、选中项滚动和同值状态复用。

```sh
npx vitest run tests/frontend/lib/app-viewport.test.ts tests/frontend/lib/app-viewport-events.test.ts tests/frontend/lib/composer-command-position.test.ts
npm run typecheck
NODE_OPTIONS=--max-old-space-size=6144 npm run build
```

大项目默认 Node 堆大小的一次构建达到内存上限；提高本地构建堆上限后完成生产前端构建。构建仍有项目已有的大 chunk 和静态/动态导入提示。

### 浏览器回归

```sh
npm run test:mobile-layout
# 可单独筛选场景名称前缀
node tests/browser/run-mobile-layout.mjs office
node tests/browser/run-mobile-layout.mjs workspace
node tests/browser/run-mobile-layout.mjs template
```

运行器优先使用 `CHROME_PATH`，否则查找本机 Edge/Chrome/Chromium；使用独立临时浏览器 profile 和 Vite 缓存，结束后关闭进程并清理临时目录。各场景在同一个本地页面中按顺序打开，避免多个 Spreadsheet Worker 同时初始化造成额外不稳定；外部网络请求被阻止，`/api/` 请求使用本地响应，不发送真实密码、创建工作区或调用供应商服务。`MOBILE_LAYOUT_OUTPUT` 可指定截图、测量结果与日志目录。

覆盖 320×568、390×844、844×390、1280×900，另有 180px 极短区域、300px 横屏区域、非零顶部偏移、模拟安全区、模拟键盘压缩、页面缩放和手动滚动。Office 使用真实 DOCX/PPTX/XLSX fixture；长表格扩展为 160 行×8 列，检查第 160 行和 H 列标记；长文本检查第 240 行末尾；损坏 OOXML 检查错误界面。PPT 模板场景使用本地成功列表与长错误响应。

一次完整浏览器运行共 56 个场景，其中 55 个通过；长 XLSX 横屏场景在等待解析 Worker 完成时超过 60 秒。使用稳定的单页会话单独运行 Office 分组后，12/12 通过。运行器将每个已完成场景的截图和矩形测量写入 `results.json`；当前本地结果目录为 `/private/tmp/aivory-mobile-layout-results-20261011`。

### 全量单元测试与基线对照

在未修改的最新 `main`（`8f1ab8278825bd2626ca6eb3039e90136a78dac2`）与本次代码上执行相同的本地前端单元测试。

隔离目录复用已有 `node_modules`，第一次默认配置遇到 11 个 URL 导入/包解析失败。后续仅在临时验证配置中允许该依赖目录、将 GSAP 内联处理，并将 worker 并行数设为 2，避免同时运行两套全量测试造成超时；仓库生产 Vite 配置没有为此改变。最终结果为：

剩余 8 个失败在基线中完全一致，分布于 6 个文件：认证 mock 缺少 `invalidateAccountRequests` 的 5 个断言、PanelFallback 旧加载图标断言、管理员审计日志旧动作文本断言、管理员排版旧字号断言。全量测试**没有全部通过**，本次没有为了改变这些无关断言而修改生产行为。

## 验证边界

- Chromium 中模拟的 `visualViewport` 和安全区能够验证坐标、尺寸和滚动逻辑；未覆盖 iOS Safari 实机键盘、真实刘海安全区或系统手势行为。
- 未连接外部 Docmee SDK/编辑服务；本次处理的是 Aivory 宿主布局与自身错误提示，未验证供应商 iframe 内部适配、线上生成、保存或文件同步。
- Office 检查覆盖所列 fixture 和滚动可达性；PDF、所有 Office 格式细节和字体像素级一致性不在本次验收中。已有 20 MiB Office 文件上限和 XLSX 250 行×50 列预览上限保持原样。

## 分步提交与分支交付

代码从最新 `origin/main` 建立隔离工作目录，避免用落后的 `dev` 覆盖已有生产改进。原 `origin/dev` 是该 `main` 的祖先，因此完成后可正常快进更新远端 `dev`，不需要强制推送。原工作目录中已分叉的本地 `dev`、`main` 不做重置。

分为五个可审阅提交：

1. 公共安全可见区域、Dialog/Sheet、兼容性宽度约束及几何/生命周期测试。
2. 密码/欢迎/工作区/设置/会话/图片蒙版等具体组件迁移与短视口回退。
3. 搜索、筛选和输入建议的定位、滚动与几何测试。
4. Office/PPT 宿主、错误界面和模板列表的剩余高度处理。
5. 本地浏览器夹具、运行器、npm 入口和详细交付文档。

完成后先推送到远端 `dev`，再基于最新远端 `main` 创建合并工作目录，以独立合并提交接入 `dev` 并正常推送 `main`。每一步提交的正文记录具体触发问题、解决方式、兼容性与本地验证。确切提交哈希和最终分支状态由本次交付回复列出。
