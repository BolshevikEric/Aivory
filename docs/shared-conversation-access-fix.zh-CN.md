# 分享对话访问失败排查与修复

## 已复现的原因

分享页面 `/share/:token` 和读取接口 `/api/public/shared/:token` 都允许免登录访问，但前端之前使用了与私有接口相同的请求处理流程。

已登录用户在新标签页打开分享链接时，页面会同时加载分享快照和恢复浏览器登录会话。如果登录恢复先完成，会出现以下顺序：

1. 分享请求记录当前 `accountRequestEpoch`。
2. `AuthGate` 完成会话恢复，`useAuth` 的用户从空值变成已登录用户。
3. 账号订阅器调用 `invalidateAccountRequests()`，递增账号请求版本。
4. 分享接口虽然成功返回，请求客户端仍将结果判为过期，抛出 `AbortError: Account changed`。
5. 分享页面此前把所有加载错误都显示成“该分享不可用”。

这可以解释为什么同一个有效链接会受登录状态和请求完成顺序影响。新增回归测试在修改前确实出现该 `AbortError`，修改后通过。

## 分步改动

### 1. 公开快照读取独立于登录会话

提交：`ad60aa58`，`fix(sharing): keep public snapshots independent of session hydration`。

- 请求客户端增加显式 `anonymous` 选项，仅为公开分享快照读取启用。
- 公开读取不发送 Cookie、Bearer、设备标识、客户端标识或请求签名。
- 登录恢复、登录退出或切换账号不会使公开快照响应失效。
- 公开请求失败不会刷新登录会话，也不会触发账号封禁、会话丢失或首次设置密码的全局处理。
- 私有接口继续丢弃账号切换前的响应；克隆分享仍走认证接口。

### 2. 区分失效链接与临时加载失败

提交：`bd1db4d3`，`fix(sharing): distinguish missing links from retryable load failures`。

| 场景 | 修复前 | 修复后 |
| --- | --- | --- |
| 接口返回 404 | 分享不可用 | 分享不可用 |
| 网络错误、429 或 500 | 分享不可用 | 加载失败提示及重试按钮 |
| 切换到另一个分享链接 | 新请求期间可能保留旧内容 | 清空旧内容并显示加载状态 |
| 旧分享请求在切换后才返回 | 已有请求有效性检查 | 继续忽略旧响应与旧错误 |

新增错误提示覆盖简体中文、繁体中文、英语、日语和法语。

### 3. 回归验证和运行说明

新增 `tests/browser/run-share.mjs`、`npm run test:share` 和测试运行文档。浏览器回归使用生产预览，避免开发模式 StrictMode 的重复 effect 干扰请求顺序；绕过 Service Worker，让 API 模拟保持在页面请求拦截层。

## 验证结果

- 分享 API、页面及身份展示测试：14 项通过。
- API 相关测试：28 项通过，其中包含上述 4 项分享 API 测试。
- 两组共覆盖 38 项不同的测试，包含私有响应的账号隔离保护。
- TypeScript：`npm run typecheck` 通过。
- 修改的 TypeScript、TSX 和浏览器脚本：ESLint 通过。
- 生产构建：TypeScript 阶段通过；Vite 在默认 2 GB Node 堆内存下耗尽内存，提高至 8 GB 后成功构建。未修改项目的构建配置或依赖版本。
- 真实 Edge 浏览器：在 1440×900、390×844、320×480 三个视口下，匿名访问、恢复登录期间加载、429 后重试、404 链接共 12 个场景通过，未发现渲染异常或页面溢出。
- 浏览器测试同时验证：开启自动 OAuth 跳转仍能匿名阅读分享，公开快照请求不携带账号凭据。

浏览器测试中先等待分享请求发出，再返回登录会话，确认页面已恢复登录后才返回分享快照，稳定覆盖了故障所需的请求顺序。

## 复查步骤与边界

运行方式见 [测试说明](../tests/README.md)。人工复查可以使用一个有效分享链接：

1. 在保留登录会话的浏览器中新开分享页面，确认对话显示正常。
2. 在未登录窗口打开同一链接，确认无需登录即可阅读。
3. 模拟分享接口返回 429、500 或网络失败，确认显示加载失败且可以重试。
4. 使用不存在或已撤销的分享 token，确认显示分享不可用。

本次验证使用本地生产产物与浏览器 API 模拟，未连接线上数据库，也未取得具体故障链接，不能据此断定所有线上访问失败都由这一竞态导致。

以下现有行为仍会使链接不可用：分享被撤销、原对话被删除、发布者失去分享权限或管理资格，以及所有者更新快照生成新 token 后继续访问旧链接。更新分享会更换 token 的行为在现有分享弹窗中已有说明，本次未改变这一规则。
