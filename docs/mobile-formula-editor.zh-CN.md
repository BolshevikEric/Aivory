# 手机端公式编辑器适配说明

本次修改覆盖聊天输入框的“插入公式”和已有公式的编辑弹窗。两处复用同一个 `FormulaEditorDialog`，因此共用这次布局修复。

## 问题与定位

用户提供的手机截图中，公式弹窗仅露出左上方的一部分，右边界和底边界接近视口的一半。该表现与全屏尺寸仍应用桌面弹窗的 `-50%` 居中位移一致。源码原有媒体规则虽然覆盖了部分移动端尺寸，但组件仍继承公共弹窗的居中类名；原生键盘和 MathLive 公式键盘也需要分别考虑可见区域变化与覆盖区域。

本次没有运行浏览器验证，因此这里记录的是截图和源码分析，不把设备上的实际样式计算结果视为已确认。

## 最终行为

| 场景 | 布局处理 |
| --- | --- |
| 视口宽度不超过 767px | 使用全屏公式编辑布局 |
| 主输入设备为粗指针，例如手机触摸屏 | 使用全屏布局，即使 WebView 报告较大的 CSS 视口宽度 |
| 可用视口高度不超过 520px | 使用全屏布局，覆盖横屏和短视口场景 |
| 普通桌面视口 | 保持弹窗布局，按实际可用区域居中 |
| 原生软键盘改变可见视口 | 跟随 `visualViewport` 的高度和顶部偏移更新尺寸 |
| MathLive 公式键盘覆盖可见视口 | 只预留键盘与可见视口实际相交的高度 |
| 手机底部存在手势安全区 | 在操作栏内部增加实际安全区间距 |

## 更改内容

### 响应式判定和定位

- 统一 CSS 和组件的移动布局判定：`(max-width: 767px), (pointer: coarse), (max-height: 520px)`。
- 在紧凑布局中，通过类名合并替换公共弹窗的 `left-1/2`、`top-1/2` 和 `[translate:-50%_-50%]`，使用贴边定位及 `[translate:0_0]`。
- 明确设置全屏弹窗的高度、最大高度和宽度，计入顶部及左右安全区，避免依赖 `height: auto` 和上下定位约束共同推算高度。
- 使用淡入效果打开移动弹窗，并禁止全屏弹窗因公共尺寸动画发生缩放。

### 可见视口和键盘

- 弹窗打开时读取可见视口，并监听窗口尺寸、媒体查询以及 `visualViewport` 的尺寸和滚动变化；关闭时移除监听并取消待执行的动画帧。
- 可见视口 API 不可用或页面处于缩放状态时，回退到窗口高度。
- 将可见高度、顶部偏移和 MathLive 键盘覆盖高度传递为公式弹窗专用 CSS 变量。
- 移除直接将键盘高度添加到弹窗底部内边距的方式，避免重复占用键盘空间。
- 移除可能超过剩余高度的固定最小高度；桌面弹窗也在键盘上方的可用区域内居中。
- MathLive 键盘显示时继续使用已有的精简编辑状态，将空间留给公式输入和确认操作。

### 输入区和底部操作

- 保留长公式和公式分类的横向滚动约束，防止内容撑宽弹窗。
- 内容滚动使用 `overscroll-contain`，限制边缘滚动向外传播。
- 移动端“取消”和“插入公式／更新公式”使用两列等宽布局，按钮最小点击高度为 44px，长标签允许换行。
- 底部操作栏直接读取 `env(safe-area-inset-bottom, 0px)`，避免依赖项目中固定为零的通用底部安全区变量。
